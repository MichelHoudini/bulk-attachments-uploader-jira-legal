Bulk Attachments Uploader for Jira

Privacy Policy

Effective date: 15 September 2026

Bulk Attachments Uploader for Jira is provided by Michel Di Lorenzo / Algomind ("we", "us"). This policy describes the app's own data handling.

The app lets an authenticated Jira user select local files, map them to existing Jira issues, validate those destinations, and upload the selected files as native Jira attachments. It uses the Jira permissions of the person using the app.

What the app does not operate

The app does not operate an external backend, database, or file storage service. It does not use third-party analytics, advertising technology, AI services, or app-specific telemetry. It does not collect Atlassian passwords, API tokens, or other Atlassian credentials.

Session processing and storage

Selected local files, CSV mapping text, and in-progress mapping and validation information are held only in the user's browser tab while the app is in use. The app does not persist them. When a file is uploaded, it becomes an attachment in the customer's Jira Cloud site and is then governed by that customer's Jira configuration and Atlassian's handling of Jira data.

How information moves

The app's Jira calls are made through Atlassian Forge's requestJira bridge to the installed Jira Cloud site. The app does not send customer data to a third-party service. It uses read:jira-work to validate target issues and write:jira-work to create attachments.

Your questions

Because the app stores no customer data outside Jira or the browser session, it has no separate app-held data to retrieve, correct, or erase. Questions about this policy or the app can be sent to algomind.atelier@gmail.com.
